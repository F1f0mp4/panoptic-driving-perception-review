# Multi-task panoptic driving perception: systematic review + replication of A-YOLOM

This folder contains everything behind the article `paper/main.pdf`:

| Folder | Content |
|---|---|
| `paper/` | Overleaf/LaTeX project (IEEEtran, one column): `main.tex`, `refs.bib`, `figures/`, `generated/` (tables generated by scripts) |
| `review/` | Systematic search, screening and data extraction: `search/` (API scripts, raw records, `merged_dedup.csv`, `screening.csv`), `included_studies.csv` (extraction table), `fulltext/` (text extracted from PDFs), `make_figures.py`, `make_tables.py` |
| `replication/` | Replication of A-YOLOM (Wang et al., IEEE T-VT 2024): scripts, pinned requirements, results (`results/*.json`, logs) |
| `YOLOv8-multi-task/` | Official A-YOLOM repository ([JiayuanWang-JW/YOLOv8-multi-task](https://github.com/JiayuanWang-JW/YOLOv8-multi-task), AGPL-3.0), commit `9cf56e8`, **unmodified**. In this GitHub repository it is a git submodule pinned to that commit; it is not included in the ZIP. |
| `data/` | Weights and BDD100K data (not included; download them as described below) |

## 1. Replication: what is reproduced

The evaluation of the two released A-YOLOM checkpoints (`v4.pt` = A-YOLOM(n), `v4s.pt` = A-YOLOM(s)) on the full
BDD100K validation split (10,000 images), using the official evaluation code with the exact settings of the
repository's `ultralytics/val.py`. We compare against the paper's Tables I–IV: vehicle recall and mAP@0.5,
drivable-area mIoU, lane balanced accuracy and lane IoU, plus parameters and FPS. No retraining.

## 2. Environment (as used)

* Apple M3 Pro (11-core CPU: 5 performance + 6 efficiency cores), 18 GB RAM, macOS 27.2.1, FP32
* Accuracy: **CPU**. Speed: Apple GPU via the PyTorch MPS backend (and CPU, batch 1)
* Python 3.10.22 (created with `uv`), PyTorch 2.2.2, torchvision 0.17.2, NumPy 1.26.4, OpenCV 4.9.0.80
* Full pinned list: `replication/requirements-lock.txt`
* Random seed: 0 (`torch.manual_seed(0)` and `np.random.seed(0)` in `eval_ayolom.py`, `torch.manual_seed(0)` in
  `fps_benchmark.py`); the evaluation itself has no randomness

The original work used Python 3.7.16 and PyTorch 1.13.1. Python ≥3.12 does not work with this 2023 code
(it needs `pkg_resources` and NumPy < 2).

## 5. Deviations from the original study

1. Hardware: Apple M3 Pro (CPU for accuracy, MPS GPU for speed, FP32) instead of NVIDIA GPUs → FPS is not comparable.
2. Software: PyTorch 2.2.2 / Python 3.10 instead of 1.13.1 / 3.7.16.
3. Evaluation of the released checkpoints only, no retraining.
4. The official speed test (`speed=True`) uses `torch.cuda.synchronize()` and cannot run without CUDA; `fps_benchmark.py`
   re-implements the same protocol with `torch.mps.synchronize()`.
5. Only the official code paths were used; the repository was not modified. Hard-coded paths of `val.py`
   (`/home/jiayuan/...`) are replaced by the wrapper's arguments.

## 6. Finding: wrong metrics on the Apple MPS backend

The first full evaluation of A-YOLOM(n) on the MPS backend gave vehicle mAP@0.5 = 44.5 % instead of 78.0 %
(`results/mps_ayolom_n.json`, `results/logs/mps_eval_n.log`). Cause: in PyTorch 2.2.2 on MPS, an in-place
`clamp_` applied to a *view* of a tensor has no effect. The official code uses this pattern in
`ultralytics/yolo/utils/ops.py::clip_boxes` (`boxes[..., 0].clamp_(0, w)`, so predicted boxes are not clipped to
the image) and in `DecSeg/val.py::update_metrics_seg` (`mask_list[count].clamp_(max=1)`).
The network forward pass itself is correct on MPS (`mps_vs_cpu_check.py`, `results/mps_vs_cpu.json`:
max. relative layer-wise difference < 3e-6). Minimal reproduction:

```bash
python replication/mps_inplace_view_repro.py     # output stored in results/mps_inplace_view_repro.txt
```

All accuracy numbers in the article are therefore computed on the CPU; MPS is used only for timing.

## 7. Parameter count

`make_paper_tables.py` counts the parameters of the released checkpoints before Conv+BN fusion (the convention of
the paper: A-YOLOM(s) gives exactly 13.61 M). A-YOLOM(n) has 3.64 M parameters, both in `v4.pt` and when built from
the repository's `yolov8-bdd-v4-one-dropout-individual-n.yaml`, whereas the paper and README report 4.43 M.
